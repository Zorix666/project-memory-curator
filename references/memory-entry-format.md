# 记忆条目格式

写入前根据目标文件复用本格式。保持内容短、可搜索、可核验；无内容的可选字段可省略，但不得省略限制或未知部分。

```markdown
## [一句话标题]

- 日期：YYYY-MM-DD
- 类型：项目上下文 / 用户偏好 / 常用命令 / 架构决策 / 风险约束
- 标签：tag1, tag2, tag3
- 适用范围：整个项目 / 指定模块 / 指定环境 / 指定命令
- 置信度：已验证 / 用户确认 / 部分验证 / 待确认

> **边界原则**：工程排障、Bug 修复、故障恢复等经验性内容**严禁混入本记忆库**，统一由 `intelligent-experience-extractor` 经验库承载。

### 内容
用简洁、可检索的语言记录结论。

### 适用场景
说明未来什么情况下应该读取或应用这条记忆。

### 依据
说明来自用户明确要求、代码验证、测试结果、构建结果、部署结果或文档事实。

### 注意事项
说明限制、例外、未知部分或不应过度推广的地方。

### 相关上下文
- 文件：相对路径
- 命令：必要时记录脱敏后的命令
- 参考：相关 issue、PR、文档或提交，如存在
```

## 预览格式

```markdown
记忆候选：<标题>
- 目标：.agent-knowledge/<文件名>
- 操作：新增 / 更新
- 结论：<一至三句>
- 依据：<可验证来源>
- 置信度：<允许值>
- 安全检查：未包含敏感信息；命令或日志已按需脱敏

请选择：保存 / 编辑 / 跳过
```

## 更新已有条目

同主题条目存在时优先更新。保留仍能解释当前约束的背景，替换已过期结论，并在"依据"或"注意事项"中说明修订原因。不要仅因日期变化复制条目。

## 待确认候选

只有确有未来价值但证据不足时才写入 `todo-memory.md`。使用 `置信度：待确认`，明确列出需要核实的问题；检索时不得把它作为事实或约束应用。
